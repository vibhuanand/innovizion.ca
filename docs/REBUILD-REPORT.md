## 1. What changed

Replaced the single-page template with a complete consultancy website: charcoal/off-white visual system, muted teal accents, original lifecycle architecture graphic, responsive navigation, technical service pages, procurement content, anonymized personnel case studies, a working email-draft enquiry flow and a print-optimized capability statement. Removed stock imagery, icon fonts, jQuery and unused template code. Retained the original hostname, contact mailbox, legacy anchors and historical licence.

## 2. Architecture

Plain static HTML, CSS, SVG and progressive JavaScript generated by a dependency-free Node build. Shared components and centralized company, procurement, services and case-study modules keep updates consistent. The committed output is compatible with the existing GitHub Pages branch/root architecture. No hosting migration, DNS change, paid service or frontend framework is required.

## Apply the packaged patch

The package contains the complete updated website, a binary-safe Git patch (including removals), previews and QA results. Apply the patch to a clean checkout rather than copying files over the old tree, which would leave retired assets behind.

```sh
git clone https://github.com/vibhuanand/innovizion.ca.git
cd innovizion.ca
git switch -c feat/innovizion-rebuild
git apply --check /absolute/path/to/Innovizion-Website-Rebuild/innovizion-rebuild.patch
git apply --index /absolute/path/to/Innovizion-Website-Rebuild/innovizion-rebuild.patch
npm test
npm run preview
```

Review the staged diff and commit it using your normal Git identity. Push the feature branch, review it, then merge to the existing `main` publishing branch. If the patch check fails because the repository has changed, reconcile those changes; do not force application or overwrite unrelated work. Keep `CNAME` unchanged. The original baseline is `1d7af7944e883b3dde049303e112f5d7d280bbc1`; rollback should use a revert commit, not deletion of the Pages deployment.
